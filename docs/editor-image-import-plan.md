# 编辑器图片导入功能设计方案

> 最后更新: 2026-06-02

## 问题

在编辑器（Edit Mode）中，用户无法方便地插入图片到 Markdown 文档。当前仅能手动输入 `![alt](path)` 语法，且需要自己确认图片路径。

## 方案 B 最终版

### 术语

| 术语 | 含义 |
|---|---|
| **导入** (Import) | 将外部图片文件复制到项目内 |
| **插入** (Insert) | 将 `![]()` markdown 语法写入 textarea 光标位置 |
| **引用** (Reference) | URL 图片直接引用链接，不复制文件 |

### 后端 API

```
POST /api/import?file=<编辑中的 .md 相对路径>
Content-Type: multipart/form-data
Body: file=<图片文件>
```

| 项 | 值 |
|---|---|
| 请求参数 | `file` — 当前编辑的 Markdown 文件相对路径 |
| 请求体 | `multipart/form-data`, 字段名 `file` |
| 验证 | 仅接收图片 MIME 类型: JPEG, PNG, GIF, WebP, SVG, BMP, TIFF, AVIF |
| 路径安全 | 复用 `validateEditPath` 模式，防目录穿越 |
| 目标目录 | `<md 文件所在目录>/images/`（不存在则创建） |
| 文件冲突 | 检测目标文件是否已存在且 size 相同 → 是则跳过写入，返回该 path；否则自动重命名 `photo.png` → `photo_1.png` → `photo_2.png` |
| 图片大小 | 无限制 |
| 写入方式 | 原子写入 (.tmp + rename) |

响应:

```json
{
  "path": "images/photo.png"
}
```

`path` 是相对于 Markdown 文件所在目录的路径，前端直接用于构造 `![](path)`。

#### 错误响应

| 状态码 | body | 场景 |
|---|---|---|
| 400 | `{"error":"missing file parameter"}` | 请求缺少 `?file=` 参数 |
| 400 | `{"error":"only image files are allowed"}` | 上传了非图片 MIME 类型的文件 |
| 403 | `{"error":"invalid file path"}` | 路径穿越检测触发 |
| 500 | `{"error":"failed to save file"}` | 文件写入失败（磁盘满、权限不足、目录创建失败等） |
| 500 | `{"error":"..."}` | 其他服务器内部错误 |

### 前端 UI

#### 工具栏按钮

在编辑工具栏新增一个按钮，位置在 Save / Cancel 右侧：

```
[Save] [Cancel] [📷 Import Image]
```

#### 导入对话框 (Import Dialog)

两个 Tab：

```
┌──────────────────────────────────────┐
│ [本地文件]  [URL]                      │
├──────────────────────────────────────┤
│                                      │
│  ┌──────────────────────────────┐    │
│  │                              │    │
│  │     拖拽图片或目录到此处      │    │
│  │     或点击选择文件            │    │
│  │                              │    │
│  │  (支持: 单图 / 多图 / 目录)   │    │
│  └──────────────────────────────┘    │
│                                      │
│          [取消]   [导入]              │
└──────────────────────────────────────┘
```

**本地文件 Tab**：
- 拖拽区：支持单张图片、多张图片、目录（递归扫描图片）
- 点击拖拽区触发文件选择器：`<input type="file" multiple accept="image/*">`
- 点击「导入」 → 批量导入所有图片 → 关闭对话框

**URL Tab**：
- 一个输入框粘贴外部图片链接
- 点击「插入」 → `![]()` 直接写入光标位置，不经导入流程

#### 待插入图片托盘 (Pending Tray)

```
┌──────────────────────────────────────────────────────────────┐
│ 待插入图片 (3)   [Insert All]                       [×]     │
│     [🖼️ a.png] [🖼️ b.png] [🖼️ c.png] ...                     │
└──────────────────────────────────────────────────────────────┘
```

- 吸附在编辑器底部（textarea 下方）
- 每张图片显示缩略图 + 文件名（横向滚动）
- 用户点击 textarea 定位光标 → 点击缩略图 → `![](path)` 插入到光标位置，尾部自动加换行 → 该图从列表移除
- **Insert All 按钮**：将所有图片按 `![](path1)\n![](path2)\n...` 格式紧凑排列，插入到光标位置，每张一行 → 清空 pending 列表
- 列表为空时自动隐藏
- 关闭托盘后，该次导入的图片不再显示（如需重新使用需重新导入）
- 最多 500 张图片

#### 拖拽到 textarea

- 从文件管理器拖拽图片或目录到 textarea 区域
- 显示 "拖拽以导入" 浮层提示
- **单张图片拖入** → 自动导入 → `![](path)\n` 直接插入之前光标位置
- **多张图片或目录拖入** → 自动导入所有图片 → 全部进入 pending tray，不自动插入

#### 剪贴板粘贴

| 来源 | 行为 |
|---|---|
| 截图工具/浏览器/图片编辑器 | 单张 → 自动导入 + `![](path)\n` 直接插入光标位置 |
| Finder/文件管理器多选文件 | 多张 → 自动导入进 pending tray，不自动插入 |

粘贴截图（无文件名）的命名规则：
```
pasted_20260602_143021.png
```

所有粘贴的图片统一保存到 `images/` 目录，不做来源路径判断。

非图片粘贴行为不变（正常粘贴文本）。

### 限制

| 项 | 值 |
|---|---|
| 图片大小 | 无限制 |
| Pending 图片数量 | 最多 500 张 |
| 支持格式 | JPEG, PNG, GIF, WebP, SVG, BMP, TIFF, AVIF |
| 目录递归深度 | 最多 10 层，防循环 |
| 非图片文件 | 静默忽略 |

### 边界情况

| 场景 | 处理 |
|---|---|
| 拖拽非图片文件到对话框 | 忽略，不触发 |
| 拖拽目录中有非图片文件 | 忽略非图片，只导入图片 |
| 导入过程中用户切换页面 | 已导入的图片保留在磁盘；pending 列表清空 |
| 粘贴非图片内容 | 忽略，正常粘贴文本 |
| 文件名含特殊字符 | 后端 sanitize，保留原文件名 |
| 目标文件已存在且 size 相同 | 跳过写入，返回已有 path 不重命名 |
| 单张图片插入 | `![](path)\n` 尾部自动加换行 |

### 涉及修改的文件

| 文件 | 改动内容 |
|---|---|
| `internal/server.go` | 新增 `handleImport` handler + `/api/import/` 路由注册 |
| `defaults/templates/layout.html` | 工具栏新增「Import Image」按钮 + 对话框 HTML + pending tray HTML |
| `defaults/static/js/editor.js` | 对话框交互、拖拽/粘贴检测、pending tray、API 调用 |
| `defaults/static/css/editor.css` | 对话框样式、pending tray 样式、拖拽浮层样式 |

### 实现阶段

1. **后端** — 新增 `handleImport`，路径验证，文件写入，原子重命名
2. **前端 HTML** — layout.html 插入按钮、对话框、tray
3. **前端 CSS** — 对话框、tray、拖拽区样式
4. **前端 JS** — 编辑器中所有交互逻辑
